# pr-publish

이 프로젝트의 Git/GitHub 마무리 담당. **코드 수정은 이미 끝난 상태에서** 호출된다.
수정 내용과 그 이유는 지금 대화에 있다 — 그걸 커밋 메시지와 PR 본문에 녹이는 것이
이 스킬의 핵심이다. `git diff`만으로는 '무엇'만 알 수 있고 '왜'는 알 수 없다.

## 쓰지 말아야 할 때

- 아직 코드를 고치는 중일 때. 수정이 끝난 뒤에 부른다.
- 커밋 없이 검증만 돌리고 싶을 때 → `pnpm typecheck` 등을 직접 실행한다.
- 사용자가 "커밋하지 마"라고 했을 때.

## 진행 순서

### 1. 현재 상태 파악

`git status --short`, `git branch --show-current`, `git diff --stat`으로 파악한다.

- 변경사항이 없으면 즉시 보고하고 멈춘다.
- **예상 밖의 파일이 섞여 있으면 멈추고 사용자에게 묻는다.** 대화에서 건드린 적 없는
  파일이 수정돼 있다면 편집기 자동 포맷 등 다른 원인일 수 있다. 임의로 커밋하거나
  되돌리지 않는다.
- `AGENTS.md`가 수정돼 있으면 그대로 포함한다. `next dev`가 다시 쓰는 파일이라
  빼봐야 또 생긴다 (AGENTS.md 자체에 그렇게 적혀 있다).

### 2. 브랜치

사용자가 이름을 지정했으면 그대로 쓴다. 아니면 `fix/설명` · `feat/설명` · `chore/설명`
형태로 짓는다 (소문자·하이픈).

- 지금 `main`이면 `main`에서 새 브랜치를 판다.
- 이미 피처 브랜치 위면 그대로 쓴다. 새로 파지 않는다.
- **코드 변경을 `main`에 직접 커밋하지 않는다.**

### 3. 검증 — 커밋보다 먼저

```
pnpm typecheck && pnpm lint && pnpm build
```

빌드 산출물(`.next`, `.velite`, `public/static`)은 전부 gitignore라 워킹트리가
더러워지지 않는다. 그래서 커밋 전에 돌리는 게 안전하다.

**하나라도 실패하면 여기서 멈춘다.** 브랜치도 커밋도 PR도 만들지 않고, 실패한
명령과 출력 끝부분을 그대로 보고한다. 실패를 스스로 고치려 들지 않는다 —
이 스킬에는 Edit/Write 권한이 없다.

### 4. 스테이징

**경로를 명시해서 add 한다. `git add -A` / `git add .` 금지.**

`.claude/settings.local.json`은 추적되지도 ignore되지도 않은 개인 권한 설정이라
`-A`를 쓰면 딸려 들어간다. 절대 스테이징하지 않는다.

`git status`로 스테이징 결과를 다시 확인하고, 파일명이 무해해 보여도 자격증명이
들어갈 만한 파일이면 내용을 먼저 열어본다.

### 5. 커밋

한국어. 제목은 `type: 요약` 한 줄, 본문은 **무엇을 왜** 고쳤는지.

- 리뷰 항목 번호가 대화에 있으면 그 번호를 그대로 쓴다 (예: "리뷰 항목 1·2·4·5").
- 여러 갈래면 불릿으로 나눈다.
- 판단이 갈렸던 지점은 왜 그렇게 골랐는지 한 줄 남긴다. 이 저장소 커밋들의 관행이다.
- 성격이 다른 변경은 커밋을 나눈다 (예: 기능 수정과 도구 설정을 한 커밋에 넣지 않는다).
- 마지막 줄: `Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>`

### 6. 푸시 & PR

```
git push -u origin <브랜치>
gh pr create --base main --title "..." --body "..."
```

PR 본문 구성:

- `## Summary` — 리뷰 항목 번호 ↔ 수정 내용 매핑. 번호가 없으면 변경 갈래별로.
- `## Test plan` — 실제로 돌린 것만 `- [x]`로. 안 돌린 건 적지 않는다.
- 마지막 줄: `🤖 Generated with [Claude Code](https://claude.com/claude-code)`

`gh`가 인증돼 있지 않으면(`gh auth status` 실패) PR 생성을 건너뛰고,
푸시까지만 한 뒤 `https://github.com/subinsad/blog/pull/new/<브랜치>` 링크와
붙여넣을 제목·본문을 보고한다. `gh auth login`을 임의로 실행하지 않는다.

## 보고

세 줄만 반환한다.

- 브랜치명
- PR 번호와 URL
- 검증 결과 한 줄 (예: `typecheck·lint·build 통과`)

`git status`·`git diff`·커밋 로그·빌드 로그 원본은 반환하지 않는다.
검증이 실패했을 때만 실패 출력을 붙인다.
