## 0. 디자인 원칙 4가지

모든 세부 결정은 이 4가지로 판정합니다. 애매하면 위쪽 원칙이 이깁니다.

1. **콘텐츠가 주인공** — UI 요소가 글보다 시선을 먼저 끌면 실패. 장식은 뺀다.
2. **조용한 인터페이스** — 색은 액센트 1개 + 무채색. 그림자보다 경계선, 채움보다 여백.
3. **밀도는 독자가 고른다** — 카드(발견) / 목록(탐색) / 카테고리(지도). 하나로 다 하려 하지 않음.
4. **다크모드는 1급 시민** — 나중에 얹는 게 아니라 토큰 설계 시점부터 두 테마를 같이 정의.

### 1.2 액센트 컬러 — ✅ 인디고 확정

| | Light | Dark | 용도 |
|---|---|---|---|
| `--accent` | `#4263EB` | `#748FFC` | 링크, 활성 상태, 포커스 링 |
| `--accent-hover` | `#3B5BDB` | `#91A7FF` | 호버 |
| `--accent-subtle` | `#EDF2FF` | `#1E2338` | 배지·활성 항목 배경 |

다크 테마에서 한 톤 밝히는 이유: `#4263EB`를 `#141517` 위에 그대로 두면 대비가 3.2:1로 AA(4.5:1) 미달입니다. `#748FFC`는 7.1:1로 여유 있게 통과합니다.

액센트는 **인터랙션에만** 씁니다. 장식·강조 목적으로 본문에 뿌리면 링크가 눈에 안 들어옵니다.

## 2. 타이포그래피

### 2.1 폰트

| 역할 | 폰트 | 로딩 |
|---|---|---|
| 본문 · UI | **Pretendard Variable** | self-host, `woff2`, `font-display: swap`, subset(한글 2350자 + Latin) |

### 2.3 본문 조판 규칙

- **컬럼 폭 720px** — 한글 17px 기준 한 줄 42~45자. 45자를 넘으면 시선 복귀가 힘들어집니다.
- 문단 간격 `1.5em`(≈26px), 문단 내 줄간 1.75
- `h2` 위 여백 `56px` / 아래 `16px`, `h3` 위 `40px` / 아래 `12px` — **위 여백을 아래의 3배 이상**으로 둬야 섹션 구분이 됩니다
- `word-break: keep-all` + `overflow-wrap: break-word` — 한글 단어가 중간에 안 잘리게 (**한국어 블로그에서 가장 자주 빠뜨리는 설정**)
- 리스트 마커는 `--fg-subtle`, 본문보다 흐리게
- 인용문(blockquote): 좌측 3px `--border-strong` 라인 + 좌패딩 20px, 배경 없음, `--fg-muted`

## 4. 컴포넌트 명세

### 4.1 ViewToggle ★재설계 — 고스트 아이콘

기존 세그먼트 pill 안은 폐기했습니다. 전용 행을 하나 잡아먹는 데다, 원칙 2(조용한 인터페이스)에 어긋납니다. 뷰 전환은 부차 기능인데 페이지에서 가장 먼저 눈에 띄면 안 됩니다.

**페이지 제목과 같은 줄, 우측 정렬. 컨테이너 chrome 없음.**

```
전체 글  42                                          ▦   ☰   ▤
──────────────────────────────────────────────────────────────
                                                     ‾‾
                                          활성 항목만 accent + 2px 언더라인
```

| 항목 | 값 |
|---|---|
| 아이콘 | Lucide `LayoutGrid` / `List` / `LayoutList`, **18px**, stroke 1.5 |
| 히트 영역 | 32×32 (시각적으로는 아이콘만, 터치 타겟은 확보) |
| 아이콘 간격 | 4px |
| 배경·테두리 | **없음** |
| 비활성 | `--fg-subtle` |
| hover | `--fg-body`, 150ms |
| 활성 | `--accent` + 아이콘 폭만큼 하단 2px accent 언더라인 |
| 인디케이터 | 항목 간 150ms 슬라이드 |

- 전체 폭 약 **104×32** — 기존안(150×36 + 전용 행) 대비 세로 44px 절약
- 라벨 텍스트 없음. `title` 툴팁 + `aria-label`("카드 보기" / "목록 보기" / "카테고리 보기")로 대체
- 각 버튼 `aria-pressed`, 그룹은 `role="group" aria-label="보기 방식"`
- 모바일(<640): 같은 자리 유지, 아이콘 20px로만 키움 (터치 정확도)

**검토했으나 채택하지 않은 안**

| 안 | 이유 |
|---|---|
| 세그먼트 pill (기존안) | 배경·테두리·패딩이 붙어 시각 무게가 과함 |
| 드롭다운 (`카드 ▾`) | 전환 비용이 클릭 2회. 자주 쓰는 기능엔 부적합 |
| 단일 순환 버튼 | 가장 작지만 다음 상태를 예측할 수 없어 발견성이 나쁨 |
| 사이드바로 이동 | 목록과 물리적으로 멀어져 연결이 안 읽힘 |

### 4.6 Tag / Badge

| 종류 | 스펙 |
|---|---|
| 카테고리 배지 | h20, padding 0 8, radius 4, 12/500, 배경 = 카테고리색 `12%` 틴트, 글자 = 카테고리색 |

**배지의 `align-self`는 카드 안에서만 씁니다.** `.card-bd`는 flex column이라 배지가 가로로 늘어나는 걸 막으려면 `align-self: flex-start`가 필요한데, 이걸 `.bdg` 기본값에 두면 목록 행(grid `align-items: center`)에서도 상속돼 배지만 위로 붙습니다.

```css
.bdg { /* align-self 없음 */ }
.card-bd > .bdg { align-self: flex-start; }   /* 카드에서만 */
.row > *      { align-self: center; }          /* 행은 전부 세로 중앙 */
```

목록 행의 자식은 높이가 제각각입니다 — 날짜 13px, 제목 15px, 배지 20px, 태그 pill 24px. 하나라도 `align-self`가 다르면 그 항목만 어긋나므로, 행 레벨에서 `.row > *`로 한 번에 못 박습니다.

### 가로 스크롤 금지

어떤 폭에서도 `documentElement.scrollWidth === clientWidth`여야 합니다. 실제로 자주 깨뜨리는 두 가지를 미리 막아뒀습니다.

- **스킵 링크**: `left: -9999px`로 숨기면 뷰포트 밖 요소가 생깁니다. `top: -9999px`로 위쪽에 숨깁니다
- **사이드바 칩 스트립**: 칩이 넘칠 때는 페이지가 아니라 **스트립 자기 안에서만** 가로 스크롤 (`overflow-x:auto` + 스크롤바 숨김)

> `overflow-x: hidden`을 `html`/`body`에 거는 방식은 쓰지 않습니다. `position: sticky` 헤더와 사이드바가 깨집니다.

## 13. 글쓰기 에디터 (`/write`)

### 13.1 왜 이게 아키텍처 결정인가

콘텐츠 정본은 Git에 있는 MDX 파일입니다. 브라우저 에디터를 붙이면 "누가 파일을 쓰느냐"가 문제가 됩니다.

| 방식 | 필요한 것 | 판단 |
|---|---|---|
| **A. 로컬 전용 에디터** | `next dev`에서만 도는 API가 `content/`에 직접 write | ✅ **채택** |
| B. 호스팅 에디터 | 로그인(GitHub OAuth) + GitHub API 커밋 + 프로덕션 쓰기 경로 | 나중에 |
| C. 에디터 없음 | VS Code / Obsidian | 반려 — 쓰는 맛이 없음 |

**A를 고른 이유**: 인증도 DB도 없이 Notion 같은 쓰기 경험을 얻고, Git이 정본이라는 원칙이 그대로 유지됩니다. 프로덕션 번들에는 에디터 코드가 아예 들어가지 않아 배포 사이즈와 공격면이 늘지 않습니다.

**대가**: 내 맥에서만 글을 쓸 수 있습니다. 폰이나 다른 기기에서 쓰고 싶어지면 B로 올려야 하고, 그때 GitHub OAuth가 붙습니다. 에디터 컴포넌트는 그대로 재사용되고 저장 계층만 교체되므로 마이그레이션 비용은 작습니다.

> **가정**: 글은 주로 이 맥에서 씁니다. 외부 기기 작성이 필수라면 이 결정을 다시 잡아야 합니다.

### 13.2 프로덕션 가드

에디터가 실수로 배포되면 누구나 글을 쓸 수 있게 됩니다. 3중으로 막습니다.

1. `/write`, `/write/[slug]`, `/api/draft` 모두 진입 시 `NODE_ENV !== 'development'` → `notFound()`
2. 헤더의 "글쓰기" 버튼도 dev에서만 렌더 (프로덕션 DOM에 흔적 없음)
3. CI에서 프로덕션 빌드 산출물에 `write` 청크가 있으면 **빌드 실패**

### 13.3 기술 선택

| 영역 | 선택 | 이유 |
|---|---|---|
| 에디터 코어 | **TipTap** (ProseMirror) | 슬래시 메뉴·버블 메뉴·입력 규칙이 1급 API |
| 마크다운 직렬화 | `tiptap-markdown` | 저장 포맷이 곧 MDX라 라운드트립이 핵심 |
| 코드 블록 | `@tiptap/extension-code-block-lowlight` | 에디터 안에서도 하이라이팅 |

**MDX 라운드트립 주의**: WYSIWYG는 JSX를 온전히 보존하지 못합니다. `<Callout>` 같은 커스텀 컴포넌트는 **원문을 그대로 들고 있는 atomic 노드**로 표현하고, WYSIWYG에서는 편집하지 않습니다. 손대야 할 때는 `⌘/`로 원문 모드로 전환합니다. 이 규칙이 없으면 저장할 때마다 컴포넌트가 조금씩 망가집니다.

### 13.5 서식 진입점 5가지

같은 명령(예: 코드 블록)에 도달하는 길이 여러 개인 건 좋습니다. 다만 **어느 순간에 무엇이 뜨는지**가 겹치면 금방 산만해집니다. 순간별로 하나씩만 배정합니다.

| 순간 | UI | 담당 | 발동 |
|---|---|---|---|
| 손을 떼기 싫을 때 | 마크다운 입력 규칙 | 블록 + 인라인 | 타이핑 중 자동 |
| 빈 줄에서 뭘 넣을지 모를 때 | 슬래시 메뉴 | **블록 삽입** | `/` |
| 텍스트를 선택했을 때 | 버블 메뉴 | **인라인 마크** | 선택 즉시 |
| 훑어보며 찾고 싶을 때 | 상단 고정 툴바 | 블록 + 인라인 | 항상 보임 |
| 특정 블록을 손볼 때 | 블록 핸들 · 우클릭 | **블록 조작** | hover / 우클릭 |

핵심 분담은 마지막 두 줄입니다. **툴바는 서식을 적용**하고, **우클릭은 블록 자체를 조작**합니다(변환·복제·이동·삭제). 둘 다 똑같은 서식 버튼을 담으면 어느 쪽을 봐야 할지 판단이 필요해지고, 그 판단이 글쓰기를 끊습니다.

슬래시 메뉴와 블록 핸들의 `+` 버튼은 **같은 컴포넌트**를 띄웁니다. 항목이 어긋날 여지를 없앱니다.

### 13.6 상단 고정 툴바

상단바(56px) 바로 아래 44px, `position: sticky`.

```
텍스트 ▾ │ B  I  U  S  <>  │ •  1.  "  │ ```  🔗  —  │ ↶  ↷        MD
─────────────────────────────────────────────────────────────────────
 블록타입   인라인 마크        목록·인용    삽입         실행취소   원문모드
```

| 항목 | 값 |
|---|---|
| 버튼 | 30×30, radius 6, 아이콘 15px |
| 그룹 구분 | 1px `--border` 세로선, 좌우 6px |
| 비활성 | `--fg-muted` |
| hover | `--bg-hover` + `--fg` |
| **활성 마크** | `--accent-subtle` 배경 + `--accent` |

- 좌측 "텍스트 ▾"는 **현재 커서가 놓인 블록 타입을 실시간 반영**합니다. 클릭하면 슬래시 메뉴와 같은 팝업이 열립니다
- 우측 끝 `MD`는 원문(MDX) 모드 토글 — 진행 방향이 다르므로 `spacer`로 떼어 놓습니다
- 툴바가 항상 보이는 건 원칙 2(조용한 인터페이스)의 예외입니다. 읽기 화면이 아니라 **작업 화면**이고, dev에서만 존재하므로 독자가 보는 정숙함에는 영향이 없습니다

#### 툴팁

모든 버튼에 `단축키 포함` 툴팁을 답니다. 아이콘만 있는 툴바는 툴팁 없이는 추측 게임이 됩니다.

- 형식: `굵게  ⌘B` — 이름 + 공백 2칸 + 단축키
- 버튼 아래 7px, 배경 `--fg` / 글자 `--bg` (반전), 11px, radius 6
- **250ms 지연 후** 페이드 인 — 툴바를 가로질러 마우스를 옮길 때 툴팁이 줄줄이 뜨는 걸 막습니다

### 13.7 슬래시 커맨드 (`/`)

빈 줄에서 `/` 입력 시 캐럿 위치에 팝업. 사용자 스크린샷의 Notion 메뉴와 같은 역할입니다.

| 그룹 | 항목 |
|---|---|
| 기본 | 텍스트, 제목 1·2·3, 불릿 목록, 번호 목록, 체크리스트, 인용, 구분선 |
| 삽입 | 코드 블록, 이미지, 표, 링크 카드 |
| 커스텀 | 콜아웃, 수식, 접기 |

- 팝업 폭 280, 항목 높이 40, 최대 높이 320 후 스크롤
- 각 항목: 20px 아이콘 + 라벨 13/500 + 우측에 마크다운 힌트 (`##`, `-`, ` ``` `)
- **한글 + 초성 검색**: `/제목` `/ㅋㄷ`(코드 블록) 모두 매칭 — 검색 팔레트(§4.8)와 같은 규칙 재사용
- `↑↓` 이동, `Enter` 삽입, `Esc` 닫기, 매칭 0건이면 자동으로 닫고 `/`를 일반 문자로 남김

### 13.8 버블 메뉴 (텍스트 선택 시)

```
┌───────────────────────────────────────────────┐
│ 텍스트 ▾ │ B  I  U  S  <>  🔗  ✏️ │ 💬 댓글 │   h36, radius 8
└───────────────────────────────────────────────┘   --bg-elevated + 1px --border
```

- 선택 영역 위 8px에 뜨고, 위 공간이 부족하면 아래로 뒤집음
- 좌측 "텍스트 ▾"는 블록 타입 변환 (제목/인용/코드로)
- 활성 마크는 `--accent-subtle` 배경 + `--accent` 아이콘
- 선택이 풀리면 100ms 후 사라짐 (즉시 사라지면 버튼을 누르러 가는 동안 없어짐)

### 13.9 색상과 크기

마크다운에는 색도 크기도 없습니다. 그래서 UI보다 **저장 형식**을 먼저 정해야 합니다.

#### 크기 = 블록 타입 (임의 px 아님)

| 항목 | px | 저장 |
|---|---|---|
| 제목 1 | 32 | `#` |
| 제목 2 | 24 | `##` |
| 제목 3 | 20 | `###` |
| 본문 | 17 | (없음) |
| 작은 글씨 | 15 | `<Caption>` |

크기 드롭다운은 px를 같이 보여주지만, 고르는 건 **타입 스케일(§2.2)의 항목**입니다. 임의 px을 허용하면 글마다 제목 크기가 달라져 목록·OG·RSS에서 일관성이 깨지고, 나중에 타이포를 한 번 조정할 때 과거 글을 전부 고쳐야 합니다.

#### 색 = 8색 토큰 팔레트 (임의 hex 아님)

| 토큰 | Light | Dark | | 토큰 | Light | Dark |
|---|---|---|---|---|---|---|
| `--m-gray` | `#868E96` | `#909296` | | `--m-yellow` | `#E67700` | `#FFD43B` |
| `--m-red` | `#E03131` | `#FF8787` | | `--m-green` | `#2F9E44` | `#8CE99A` |
| `--m-orange` | `#E8590C` | `#FFC078` | | `--m-blue` | `#1971C2` | `#74C0FC` |
| `--m-violet` | `#6741D9` | `#B197FC` | | `--m-pink` | `#C2255C` | `#FAA2C1` |

배경(형광펜)은 같은 토큰을 `color-mix`로 18~26% 틴트해서 씁니다. 노랑만 26%인데, 다른 색과 같은 20%로는 눈에 안 띄기 때문입니다.

**임의 hex을 막는 진짜 이유는 다크모드입니다.** 라이트에서 고른 `#1971C2`를 다크 배경 `#141517`에 그대로 두면 대비가 3.2:1로 AA에 미달합니다. 토큰으로 저장하면 테마별 값이 자동으로 갈립니다. §1.3에서 세운 원칙(컴포넌트는 원시값을 직접 참조하지 않는다)의 연장입니다.

#### 저장 형식

```mdx
velite는 <Mark c="blue">타입 안전</Mark>한 파이프라인을 만들어준다.
<Mark bg="yellow">여기가 핵심이다.</Mark>

<Caption>그림 1. 빌드 파이프라인</Caption>
```

- 본문은 여전히 읽히는 마크다운이고, 색이 필요한 구간만 짧은 컴포넌트로 감쌉니다
- `Mark`는 `c`/`bg`를 **토큰 이름으로만** 받습니다. 유효하지 않은 값이면 빌드 실패
- 렌더링 시 `var(--m-{name})`으로 치환되므로 테마 전환이 공짜입니다

#### UI

| 컨트롤 | 위치 | 내용 |
|---|---|---|
| `A ▾` | 툴바 · 버블 메뉴 | 글자 색 8 + 배경 색 8, 32×32 스와치 4열 |
| `Aa ▾` | 툴바 | 크기 5단, 우측에 px 표기 |

- 버블 메뉴에도 `A`를 둡니다. 텍스트를 막 선택한 직후가 색을 칠하는 가장 흔한 순간입니다
- 현재 글자 색은 툴바 스와치에 반영
- **색을 적용할 때 기존 `c-*`/`bg-*` 스팬은 먼저 제거하고 다시 감쌉니다.** 중첩되면 어느 색이 이겼는지 알 수 없고 다크모드 계산도 어긋납니다
- 선택 영역은 `selectionchange`마다 저장합니다. 팝오버를 열 때만 저장하면, 열어놓고 다른 곳을 거친 뒤 색을 고를 때 엉뚱한 곳에 칠해집니다

#### 남용 방지

색은 가장 싸고 가장 빨리 망가지는 강조 수단입니다. 원칙 2를 지키려면 제약이 필요합니다.

- 한 글에 **색 2종까지** 권장 — 초과 시 린트 경고
- 링크가 이미 `--accent`(인디고)이므로 **파랑 글자색은 링크와 혼동**됩니다. 파랑은 배경색으로만 쓰기를 권장
- 색만으로 의미를 전달하지 않습니다(§7). 빨강으로 "위험"을 표현할 거면 콜아웃 블록을 쓰는 게 맞습니다

### 13.10 블록 핸들 · 우클릭 메뉴

블록에 마우스를 올리면 좌측 여백에 컨트롤 두 개가 나타납니다.

```
  +  ⋮⋮  │ ## 왜 옮겼나
          │
          │ 가장 큰 이유는 Next.js 15 App Router와의…
   ↑   ↑
   │   └ 블록 메뉴 (우클릭과 동일)
   └ 아래에 블록 추가 → 슬래시 메뉴 팝업
```

- 컨트롤 22×22, 본문 좌측 밖 54px 지점 (본문 폭 720을 침범하지 않음)
- 평소엔 숨어 있다가 hover에서만 노출 — 빈 화면이 버튼으로 덮이지 않게

#### 메뉴 내용

| 그룹 | 항목 |
|---|---|
| 전환 | 텍스트 / 제목 1·2·3 / 인용 / 코드 블록 |
| 조작 | 복제 `⌘D`, 위로 `⌘⇧↑`, 아래로 `⌘⇧↓`, 블록 링크 복사 |
| 삭제 | 삭제 `⌘⌫` — hover 시에만 빨강 |

- **현재 블록 타입은 전환 목록에서 제외**합니다. 이미 제목 2인 블록에 "제목 2로 전환"이 보이면 잘못 읽힙니다
- 폭 224, 항목 높이 34, 우측에 단축키
- 화면 오른쪽 끝에서 열리면 메뉴가 잘리므로 `left`를 `viewport - 224 - 16`으로 clamp

#### 브라우저 기본 메뉴 문제

우클릭을 가로채면 붙여넣기·맞춤법 검사 같은 브라우저 기본 메뉴가 사라집니다. 실제로 자주 불편해지는 지점입니다.

- **`⇧` + 우클릭이면 가로채지 않고** 브라우저 기본 메뉴를 그대로 띄웁니다
- 우리 메뉴 하단에 `⇧ + 우클릭 → 브라우저 기본 메뉴` 안내를 상시 표기

### 13.11 마크다운 입력 규칙

타이핑 중 자동 변환. 마크다운을 아는 사람이 손을 안 떼게 하는 장치입니다.

| 입력 | 결과 | | 입력 | 결과 |
|---|---|---|---|---|
| `# ` | 제목 1 | | `> ` | 인용 |
| `## ` | 제목 2 | | ` ``` ` | 코드 블록 |
| `### ` | 제목 3 | | `---` | 구분선 |
| `- ` `* ` | 불릿 | | `**굵게**` | **굵게** |
| `1. ` | 번호 | | `` `코드` `` | 인라인 코드 |

**저장 포맷은 그냥 마크다운입니다.** 에디터가 보여주는 건 렌더링된 블록이지만, 파일에 기록되는 건 ` ``` ` 와 `##` 가 그대로 들어간 텍스트입니다. 그래서 같은 글을 VS Code에서 열어 고쳐도 되고, Git diff도 읽힙니다. 에디터는 파일 포맷을 바꾸지 않고 **쓰는 방법만 하나 더** 얹는 것입니다.

**변환 취소**: 입력 규칙이 발동한 직후 `⌘Z`를 누르면 변환만 취소되고 입력한 문자(` ``` `)가 리터럴로 남습니다. ProseMirror 기본 동작이고, 마크다운 문법 자체를 글에 써야 할 때 필요합니다.
| `[] ` | 체크박스 | | `~~취소~~` | 취소선 |

### 13.12 저장

**자동 저장은 브라우저에만 한다.**

프로덕션에서 저장은 곧 저장소 커밋이다. 입력 3초 debounce로 커밋하면 글 하나 쓰는 동안 커밋이 수십 개 쌓이고 히스토리가 못 쓰게 된다. 그래서 자동 저장은 `localStorage` 까지만 가고, 커밋은 사람이 누를 때만 일어난다.

| 시점 | 어디에 | 표시 |
|---|---|---|
| 타이핑 후 600ms | localStorage | `● 브라우저에만 저장됨` |
| 저장 · 발행 버튼, `⌘S` | 저장소 | `저장소에 저장됨 · 방금` + 커밋 링크 |

- **문구가 정확해야 한다.** "저장됨"이라고만 쓰면 저장소에 들어간 줄 알고 탭을 닫는다. 브라우저에만 있는 상태는 그렇게 말해야 하고, 주황 점을 함께 띄운다
- 커밋 안 된 변경을 들고 탭을 닫으려 하면 `beforeunload` 로 막는다
- 커밋 성공 시 로컬 초안을 지운다. 안 지우면 다음 진입 때 낡은 초안이 되살아난다

| 환경 | 저장 위치 | 반영 |
|---|---|---|
| 개발 | `content/posts/{연도}/{slug}/index.mdx` | 즉시 (velite watch) |
| 프로덕션 | 저장소 커밋 | Vercel 재빌드 후 1~2분 |

- slug은 제목에서 자동 생성(한글 → 로마자), 우측 패널에서 수동 수정 가능
- **발행**: `draft: false` 로 바꾸고 커밋
- slug이 그대로 파일 경로가 되는 자리라 화이트리스트 정규식 + 루트 이탈 검사를 둘 다 건다
